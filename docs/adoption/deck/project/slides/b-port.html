BACKUP · LAB TO PRODUCTION

What changes in production

In the labIn production
Expected list from Ansible’s inventoryFrom your pipeline the same way: CMDB, deployment-server serverclasses or Terraform. One source for inputs and expectations.
One search headA search-head cluster replicates the KV store. Each collection keeps its known writers; run the scheduled writer on one member.
One Cribl instanceOne expected row and relay per worker group: a macro change, not yet tested.
Index-time parsingCribl-delivered data gets no index-time rules: do line breaking and rewrites in Cribl or on the agent.
Test block in CriblTreat it as a privileged change: a block control can blind monitoring too.
Dashboard risky-command check offKeep it on, and accept one “Run Query” click on Manage’s writes.
14-day retentionEvery lookback must stay inside your shortest retention; a test checks it.
None of these is a redesign, but two are not yet proven: the search-head cluster and more than one Cribl worker group were never tested in the lab. The app is search-time SPL plus the KV store, with no scripts and no index-time config, so it moves with Splunk Enterprise. The biggest piece of work is the inventory feed, which is roadmap feature F3.
